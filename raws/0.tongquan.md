# LỘ TRÌNH 28 NGÀY

## Chứng khoán chuyên sâu dành cho Fullstack Developer

Mục tiêu: Trang bị kiến thức nghiệp vụ chứng khoán Việt Nam kết hợp với kiến trúc hệ thống phần mềm, giúp Fullstack Developer có khả năng tham gia phát triển, bảo trì và debug các hệ thống của công ty chứng khoán.

Thời gian: 28 ngày (4 tuần), khoảng 90–120 phút/ngày.

Phương pháp: Học nghiệp vụ → Phân tích hệ thống → Thiết kế API/Database → Thực hành lập trình → Debug.

Dự án xuyên suốt: Securities Trading Simulator.

## Tuần 1 — Nền tảng thị trường chứng khoán

Ngày 1–7

Mục tiêu: Hiểu thị trường chứng khoán Việt Nam, các loại chứng khoán, bảng giá và nguyên lý giao dịch.

| Ngày | Chủ đề                           | Nội dung nghiệp vụ                                 | Thực hành kỹ thuật                           |
| ---- | -------------------------------- | -------------------------------------------------- | -------------------------------------------- |
| 01   | Tổng quan thị trường chứng khoán | Các chủ thể, HOSE, HNX, UPCoM, luồng giao dịch     | ERD, API danh mục mã chứng khoán             |
| 02   | Cổ phiếu và tài sản tài chính    | Cổ phiếu, trái phiếu, ETF, mã chứng khoán          | Thiết kế Security Master Data Service        |
| 03   | Cấu trúc bảng giá                | Giá tham chiếu, trần/sàn, dư mua/dư bán, khớp lệnh | Market Data API, Redis, WebSocket            |
| 04   | Phiên và phương thức giao dịch   | Khớp lệnh liên tục, định kỳ, ATO/ATC, LO           | Trading Session State Machine                |
| 05   | Khớp lệnh và sổ lệnh             | Price-time priority, Order Book, Partial Fill      | Mô phỏng Matching Engine                     |
| 06   | Tài khoản giao dịch              | Khách hàng, tiểu khoản, số dư tiền và chứng khoán  | Account Schema, Balance API                  |
| 07   | Ôn tập và Mini Project           | Tổng hợp nghiệp vụ giao dịch                       | Xây dựng bảng giá và luồng đặt lệnh đơn giản |

Kết quả tuần 1: Đọc hiểu bảng giá chứng khoán, giải thích được quy trình giao dịch và xây dựng được nền tảng dữ liệu chứng khoán cùng bảng giá mô phỏng.

## Tuần 2 — Nghiệp vụ chuyên sâu công ty chứng khoán

Ngày 8–14

Mục tiêu: Hiểu quy trình đặt lệnh, quản lý tài khoản, tiền, tài sản, margin và các nghiệp vụ hậu giao dịch.

| Ngày | Chủ đề               | Nội dung nghiệp vụ                                  | Thực hành kỹ thuật               |
| ---- | -------------------- | --------------------------------------------------- | -------------------------------- |
| 08   | Vòng đời lệnh        | New, Pending, Accepted, Filled, Cancelled, Rejected | Order State Machine              |
| 09   | Đặt, sửa, hủy lệnh   | Kiểm tra tính hợp lệ, sức mua, chống trùng lệnh     | Order REST API                   |
| 10   | Quản lý tiền         | Available Balance, Reserved Balance, Unsettled Cash | Cash Ledger, Balance Reservation |
| 11   | Quản lý danh mục     | Holdings, Cost Basis, Unrealized/Realized P&L       | Portfolio Service API            |
| 12   | Margin và sức mua    | Margin Loan, Collateral, Risk Rules                 | Buying Power Calculator          |
| 13   | Thanh toán và lưu ký | Clearing, Settlement, Depository, Reconciliation    | Settlement Records & Processing  |
| 14   | Ôn tập nghiệp vụ     | Tình huống đặt lệnh lỗi và sai lệch số dư           | Thiết kế OMS Database            |

Kết quả tuần 2: Hiểu vòng đời giao dịch từ đặt lệnh đến hậu giao dịch; có khả năng phân tích yêu cầu nghiệp vụ và thiết kế hệ thống quản lý lệnh (OMS).

## Tuần 3 — Kiến trúc hệ thống chứng khoán & Fullstack Engineering

Ngày 15–21

Mục tiêu: Nắm kiến trúc các hệ thống chứng khoán, cơ chế realtime, giao tiếp bất đồng bộ và những vấn đề quan trọng về tính nhất quán dữ liệu.

| Ngày | Chủ đề                       | Nội dung nghiệp vụ / kỹ thuật                   | Thực hành                        |
| ---- | ---------------------------- | ----------------------------------------------- | -------------------------------- |
| 15   | Kiến trúc tổng thể CTCK      | Trading, OMS, RMS, Market Data, Back Office     | System Context Diagram           |
| 16   | API Gateway & Authentication | Session, MFA, xác thực giao dịch, phân quyền    | API Security Design              |
| 17   | Realtime Market Data         | Streaming, Snapshots, Deltas, Sequence          | WebSocket Server/Client          |
| 18   | Event-driven Architecture    | Events, Kafka/RabbitMQ, Retry, Ordering         | Event Schema, Consumer           |
| 19   | Concurrency & Consistency    | Locking, Isolation, Idempotency                 | Chống trùng lệnh, Race Condition |
| 20   | Database & Transactions      | ACID, Ledger, Indexes, Transactional Outbox     | Thiết kế Transactional Database  |
| 21   | Ôn tập kiến trúc             | Latency, Throughput, Failure Modes, Scalability | System Design Review             |

Kết quả tuần 3: Thiết kế được kiến trúc hệ thống giao dịch mô phỏng, hiểu luồng dữ liệu realtime và biết cách xử lý các vấn đề về concurrency, distributed transactions và event consistency.

Ngày 22–28

| Ngày | Chủ đề                     | Nội dung                                               | Thực hành                 |
| ---- | -------------------------- | ------------------------------------------------------ | ------------------------- |
| 22   | Frontend Trading Dashboard | Quotes, Order Entry, Holdings                          | Trading UI bằng React     |
| 23   | Order Management Service   | Order Validation, Order Lifecycle                      | OMS Backend Service       |
| 24   | Risk & Balance Service     | Buying Power, Cash Reservation, Risk Check             | Risk Service              |
| 25   | Matching Engine mô phỏng   | Partial Fill, Order Matching, Execution Events         | Matching Simulator        |
| 26   | Logging & Observability    | Trace ID, Metrics, Audit Trail                         | Monitoring & Tracing      |
| 27   | Debug tình huống thực tế   | Timeout, Duplicate Orders, Race Conditions, Stale Data | Incident Investigation    |

Kết quả tuần 4: Hoàn thiện Mini Trading Platform với dữ liệu giả lập, có giao diện, API, database, realtime, quản lý lệnh, mô phỏng khớp lệnh và logging để debug.

### 5 năng lực quan trọng nhất cần đạt

1. Domain Knowledge: Hiểu nghiệp vụ giao dịch, quản lý lệnh, tiền và tài sản.
2. System Design: Phân tích kiến trúc OMS, Market Data, Portfolio, Risk và Back Office.
3. Backend Engineering: Thiết kế API, database, transaction và cơ chế xử lý đồng thời.
4. Frontend Engineering: Xây dựng Trading Dashboard có khả năng cập nhật realtime.
5. Debugging: Truy vết lỗi từ frontend qua backend, database, cache, message broker và hệ thống tích hợp.

Định hướng trọng tâm: Đối với Fullstack Developer tham gia dự án công ty chứng khoán, nên dành nhiều thời gian nhất cho tuần 2 và tuần 3, đặc biệt là Order Management System, quản lý số dư, concurrency, event-driven architecture và data consistency. Đây là những kiến thức có giá trị cao khi đọc hiểu codebase và debug các nghiệp vụ giao dịch phức tạp.
